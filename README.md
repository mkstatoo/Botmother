# 🏭 کارخانه ربات — ساخت ربات تلگرام برای ارائه‌دهندگان محتوای صوتی و ویدئویی

یک ربات تلگرام («ربات مادر») که به هر سازنده‌ی محتوا اجازه می‌دهد با دادن توکن، **ربات اختصاصی خودش** را بسازد و مدیریت کند. همه‌ی ربات‌ها در یک پروسه و یک دیتابیس اجرا می‌شوند (aiogram 3 + SQLAlchemy async).

## امکانات

**برای سازنده (از طریق ربات مادر)**
- ساخت ربات با توکن BotFather؛ توکن رمزنگاری (Fernet) ذخیره می‌شود و پیام حاوی توکن از چت پاک می‌شود
- توقف/فعال‌سازی، تغییر توکن (همان ربات)، حذف کامل ربات و داده‌هایش
- سقف تعداد ربات برای هر کاربر

**پنل مدیریت داخل هر ربات (`/panel`)**
- **افزودن محتوا**: کافی است فایل صوتی/ویدئو/ویس/ویدئو‌پیام/سند را برای ربات بفرستید → عنوان، توضیح، دسته، نوع دسترسی، قیمت → لینک اشتراک‌گذاری (`t.me/ربات?start=c_ID`)
- **ذخیره‌سازی ترکیبی** (به‌ازای هر محتوا): آپلود مستقیم در تلگرام (file_id) · کانال خصوصی ذخیره‌ساز (کپی از کانال؛ اگر پیام کانال پاک شود به file_id برمی‌گردد) · لینک خارجی
- **محتوای رایگان با شرط اسپانسر**: تا ۵ کانال؛ کاربر باید عضو همه باشد و عضویت **هر بار قبل از ارسال** بررسی می‌شود (مشترکین معاف‌اند). اگر یک کانال قابل‌بررسی نباشد، کاربر قفل نمی‌شود
- **محتوای ویژه**: خرید تکی و/یا اشتراک (پلن‌های دلخواه؛ تمدید روی اشتراک جاری جمع می‌شود)
- **سه روش پرداخت** (وجه مستقیم به حساب خودِ سازنده می‌رود):
  - درگاه بانکی **زرین‌پال** (مبلغ به تومان)
  - **ارز دیجیتال** با NOWPayments (مبلغ به دلار؛ تأیید با امضای IPN)
  - **واریز دستی** (کارت‌به‌کارت یا آدرس کیف پول): کاربر رسید می‌فرستد، سازنده با یک دکمه تأیید/رد می‌کند
- دسته‌بندی، جستجو، آمار (کاربران، دریافت‌ها، فروش، پردانلودترین‌ها)، ارسال همگانی با محدودیت سرعت، پیام خوش‌آمد سفارشی
- جلوگیری از فوروارد/ذخیره (`protect_content`) و **حذف خودکار** فایل از چت کاربر پس از مدتی

**مدیریت پلتفرم (`/admin` در ربات مادر، برای `ADMIN_IDS`)**: آمار کل، لیست ربات‌ها، مسدود/آزاد کردن ربات، پیام به همه‌ی سازندگان.

## نصب و اجرا

```bash
cd botfactory-aiogram
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # BOT_TOKEN و ADMIN_IDS را پر کنید
python -m botfactory
```

با Docker: `cp .env.example .env && docker compose up -d --build`

**استقرار کامل روی سرور (HTTPS خودکار، پشتیبان‌گیری، به‌روزرسانی): [DEPLOY.md](DEPLOY.md)**

### تنظیمات مهم (`.env`)

| متغیر | توضیح |
|---|---|
| `BOT_TOKEN` | توکن ربات مادر (اجباری) |
| `ADMIN_IDS` | آیدی عددی ادمین‌های پلتفرم |
| `MODE` | `polling` (پیش‌فرض، بدون دامنه) یا `webhook` (نیاز به `BASE_URL` با https) |
| `BASE_URL` | آدرس عمومی سرور. **برای زرین‌پال و NOWPayments لازم است** (بازگشت از درگاه) |
| `PROXY_URL` | پروکسی برای دسترسی به تلگرام (`socks5://…` یا `http://…`) |
| `DATABASE_URL` | SQLite (پیش‌فرض) یا `postgresql+asyncpg://…` |
| `FERNET_KEY` | کلید رمزنگاری؛ خالی = ساخت خودکار در `data/fernet.key`. **حتماً پشتیبان بگیرید** |

## راه‌اندازی یک ربات برای سازنده (بدون دانش فنی)

1. در ربات مادر «ساخت ربات جدید» را بزنید؛ راهنمای قدم‌به‌قدم گرفتن توکن از BotFather (با دکمه‌ی باز کردن BotFather) نمایش داده می‌شود. توکن را بفرستید.
2. بلافاصله «⚡ تنظیم سریع» شروع می‌شود؛ چند سؤال ساده، هر کدام قابل رد شدن:
   - پیام خوش‌آمد
   - فروش محتوای پولی؟ ← شماره کارت (۱۶ رقم، اعداد فارسی هم قبول) و نام صاحب کارت
   - اشتراک ماهانه؟ ← قیمت به تومان (پلن ۳۰ روزه ساخته می‌شود)
   - کانال اسپانسر؟ ← راهنمای ادمین‌کردن ربات + ارسال @آیدی یا فوروارد یک پیام از کانال (ادمین‌بودن ربات همان لحظه بررسی می‌شود)
3. در پایان دکمه‌ی «⚙️ باز کردن پنل ربات» (لینک `t.me/ربات?start=panel`) مستقیم پنل مدیریت را داخل ربات خودِ سازنده باز می‌کند (فقط برای مالک؛ برای بقیه منوی عادی). از همان‌جا هر فایل صوتی/ویدئو را بفرستید تا ثبت شود.
4. هر زمان می‌توان از «🤖 ربات‌های من ← ⚡ تنظیم سریع» دوباره آن را اجرا یا از پنل جزئیات را تغییر داد.

**تنظیمات پیشرفته (از پنل):**
- **کانال ذخیره‌ساز** (اختیاری): کانال خصوصی بسازید، ربات را با اجازه‌ی ارسال پیام ادمین کنید → پنل ← تنظیمات.
- **درگاه بانکی/ارز دیجیتال**: پنل ← پلن‌ها و پرداخت ← مرچنت‌کد زرین‌پال / کلیدهای NOWPayments (فقط «API Key» و «IPN Secret» لازم است).

## نکات استقرار (مهم)

- **تلگرام فیلتر و زرین‌پال داخلی**: سرور داخل ایران معمولاً به تلگرام دسترسی ندارد و سرور خارج از ایران ممکن است از زرین‌پال خطا بگیرد. دو راه: (الف) سرور داخل ایران + `PROXY_URL` برای تلگرام؛ (ب) سرور خارج + یک رله/پروکسی در ایران که به زرین‌پال می‌رسد و آدرسش در `ZARINPAL_BASE` قرار می‌گیرد.
- پشت یک reverse proxy با HTTPS قرار دهید و `BASE_URL` را همان آدرس بگذارید.
- برای هر سازنده، ربات باید حداقل یک‌بار `/start` شده باشد تا بتواند به او پیام (فروش جدید، رسید) بدهد.
- فایل‌های بسیار حجیم را بهتر است در کانال ذخیره‌ساز یا با لینک خارجی نگه دارید.
- `file_id`ها مخصوص همان ربات‌اند؛ اگر ربات را عوض کنید، محتوای «کانال ذخیره‌ساز» همچنان قابل ارسال است ولی محتوای «مستقیم» باید دوباره آپلود شود.

## امنیت
- توکن ربات‌ها، مرچنت‌کد و کلیدهای درگاه با Fernet رمزنگاری می‌شوند؛ پیام‌های حاوی این اطلاعات از چت پاک می‌شوند.
- وب‌هوک تلگرام هم با مسیر مخفی و هم با هدر `X-Telegram-Bot-Api-Secret-Token` احراز می‌شود.
- زرین‌پال: تأیید فقط با `verify` سمت سرور، با مبلغ ذخیره‌شده در دیتابیس (نه مبلغ ارسالی کاربر). NOWPayments: امضای HMAC-SHA512 + تطبیق شناسه سفارش و مبلغ.
- تحویل خرید **idempotent** است: تکرار کال‌بک یا IPN باعث ارسال دوباره یا ثبت دوباره نمی‌شود.
- هر دکمه/کال‌بک مالکیت ربات و سطح دسترسی را دوباره بررسی می‌کند (کاربر عادی به پنل دسترسی ندارد).

## تست
```bash
pip install pytest pytest-asyncio
python -m pytest tests -q
```
تست‌ها بدون اینترنت اجرا می‌شوند: یک تلگرام شبیه‌سازی‌شده (ثبت تماس‌ها)، سرورهای شبیه‌ساز زرین‌پال/NOWPayments و دیتابیس SQLite موقت. سناریوها: ساخت ربات، جادوگر تنظیم سریع و لینک پنل، آپلود و ویرایش محتوا، کانال ذخیره‌ساز، شرط اسپانسر، خرید با هر سه روش، اشتراک و تمدید، حذف خودکار، ارسال همگانی، وب‌هوک‌ها، راه‌اندازی/توقف کامل برنامه در دو حالت polling و webhook، و ابطال توکن.

## محدودیت‌ها و نکته‌های صادقانه
- ارتباط واقعی با تلگرام، زرین‌پال و NOWPayments در محیط ساخت **قابل آزمایش نبود**؛ رفتار آن‌ها با شبیه‌ساز و بر اساس قرارداد API آزموده شد. قبل از انتشار، یک ربات آزمایشی و یک پرداخت کوچک واقعی از هر درگاه انجام دهید. مستندات زرین‌پال از محیط ساخت قابل خواندن نبود؛ بنابراین مسیرهای `request.json` و `verify.json` نسخه‌ی ۴ طبق قرارداد شناخته‌شده پیاده شد و مبلغ‌ها به **ریال** ارسال می‌شود.
- کمیسیون پلتفرم پیاده‌سازی نشده است (وجه مستقیم به درگاه سازنده می‌رود).
- مراحل گفتگو (FSM) پیش‌فرض در حافظه است؛ با ری‌استارت، مراحل نیمه‌کاره پاک می‌شوند (برای ماندگاری `REDIS_URL` بدهید).
- متن‌ها فارسی‌اند؛ برای زبان دیگر باید رشته‌ها در `botfactory/child/*.py` و `botfactory/mother/router.py` ترجمه شوند.
